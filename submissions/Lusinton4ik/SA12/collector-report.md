Рабочая ветка: `student/Lusinton4ik/SA12-worker`, checkout `C:/Users/lyudm/orca/workspaces/Training/SA12-worker`. Реализован CLI с чтением DOM через Orca, закреплённым page ID и ограниченным временем subprocess. Атомарный checkpoint хранит записи по id, завершённые и ожидающие страницы, ошибки и состояние завершённости; JSON/CSV и errors восстанавливаются из checkpoint. ## Исправление по первому ревью

При `goto` с `result.effects.loading: true` сборщик теперь вызывает `orca wait --page ID --load load --json` до чтения DOM. Фактический URL после `eval` должен совпасть с запрошенным, иначе сбор завершается ошибкой. При отсутствии `loading: true` лишнего ожидания нет.

Команда целевой проверки та же, что выше. RED: 9 тестов, 2 ожидаемых отказа — прочитан старый URL до wait и не отклонён несовпадающий URL. GREEN: 9 тестов, OK, exit 0. Полный вывод обоих запусков добавлен в `evidence/collector-tests.txt`. Тесты подменяют границу subprocess; реальный сбор не выполнялся. Ограничение по недоступному pytest сохраняется.

## Исправление nullable-полей и прежнего checkpoint

Реальное наблюдение P021 показало строку `None` в DOM характеристик. Нормализация сохраняет её как null только в availability, ram_GB, ssd_GB и screen_inches; ключи обязательны. Целочисленные поля преобразуются в int, screen_inches при наличии — в float. Остальные обязательные поля и повреждённые числовые значения отклоняются. CSV сохраняет null как пустое поле.

Для восстановления прежних 20 записей загрузка checkpoint переводит старое availability `"None"` в null и числовой screen_inches в float. Преобразование выполняется в памяти; при другой ошибке валидации исходные файлы не изменяются. RED и GREEN обоих изменений добавлены в `evidence/collector-tests.txt`. Финальная команда unittest из раздела проверок: 15 тестов, OK, exit 0; восстановление и экспорт проверены через fake browser. Реальный браузерный сбор в этом раунде не запускался; ограничения общей проверки pytest сохраняются.

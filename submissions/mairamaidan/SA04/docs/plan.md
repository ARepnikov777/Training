# SA04 Implementation Plan

> **For agentic workers:** Use subagent-driven-development. Требования конкретной подзадачи — в briefs/, общий контракт — interfaces.md.

**Goal:** Одной командой получить clean.csv, rejected.csv и report.md по H07 и доказать воспроизводимость.
**Architecture:** Очистка возвращает данные и счётчики; отчёт принимает их без повторной очистки. CLI объединяет два небольших модуля. Отдельная проверка сопоставляет результат исходным строкам и эталону.
**Tech Stack:** Python 3, стандартная библиотека, unittest; без новых runtime-зависимостей.
**Spec:** ../source/issue-55.md и неизменяемый materials/H07/.

## Global Constraints

- Область записи: submissions/mairamaidan/SA04/. Только native agent_type explorer/worker/reviewer.
- Не менять materials/, downloads/, общие инструменты и чужие результаты. Один пишущий агент на worktree.
- TDD: утверждение требуемого поведения должно падать до реализации, не из-за ошибки импорта. Разрешён временный минимальный вызываемый каркас; его заглушка не остаётся в результате.
- Контроль: 8 строк, 4 уникальных, 1 повтор, 3 отклонения A5–A7, 1000 KZT; Еда 500, Транспорт 200, Канцелярия 300.
- Публичный запуск и все выходы детерминированы; исходная строка/источник/причина сохраняются.
- Реальные журналы и отчёты, без вымышленных запусков/проверок. Секреты не читать и не сохранять.

## Preflight: конфликты и решения

| Область | Проверка | Решение |
|---|---|---|
| T1 | read-only отчёт и файлы результата | Сохраняет координатор, explorer ничего не пишет |
| T2 | граф требует explorer до окончательного контракта | Управляющий граф сохраняется до explorer, контракт уточняется после фактов |
| T3 ↔ T4 | передаваемые строки/счётчики | Один interfaces.md, непересекающиеся файлы и worktree |
| T3/T4 ↔ T5 | общая точка входа | Только T5 владеет pipeline.py; координатор интегрирует после проверки обоих |
| T5 ↔ T6 | независимость ревью | reviewer не реализует, отчёт сохраняет координатор |
| T3 | запрет импортного RED | Минимальный вызываемый каркас, затем утверждение поведения падает |
| T4 | отсутствие cleaning.py в worktree | Контрактные fixture-данные без импорта cleaning |
| T5 | проверка не копирует производственный алгоритм | Отдельное сопоставление строк/артефактов и фиксированный эталон |
| T6 | финальная приёмка и GitHub | Локальное Done отдельно от одобрения/merge преподавателем |

Ruling: план и брифы хранятся внутри разрешённой области; scratch SDD вне deliverable не публикуется. Параллельные worker разрешены спецификацией #55 и изолированы, что приоритетнее общего запрета параллельной реализации в SDD-скилле. Полученное поручение выполнить веху включает её сдачу одним учебным PR, без merge.

# SA04 — контракт v1, утверждён до реализации

Источники: #55, H07 input/rules.json и checks/expected.json; факты explorer сверены координатором. Python 3.9+ и стандартная библиотека. Исполнители не меняют этот файл.

## Cleaning

`src.cleaning.clean_files(paths, rules) -> dict`

- paths: последовательность pathlib.Path в заданном порядке, UTF-8 CSV с заголовком ровно `id,date,category,amount`.
- rules: dict из rules.json; категории берутся из rules['categories'].
- Возврат: `{'clean': [...], 'rejected': [...], 'stats': {...}}`.
- clean: список dict с полями `id,date,category,amount`; category — русское отображение; amount — строка конечного неотрицательного Decimal в десятичном формате без экспоненты (без принудительного округления). Порядок первых корректных появлений.
- rejected: список dict `source,line_number,raw_line,id,reason`; source — имя входного файла, line_number — номер первой физической строки записи (int), raw_line — точный исходный текст записи без завершающего перевода строки. Сохранять quoting; в выходном CSV raw_line экранирует csv.DictWriter.
- stats: целые `source_rows,clean_rows,duplicate_rows,rejected_rows`; заголовки не считаются. Баланс source_rows = clean_rows + duplicate_rows + rejected_rows.
- Дата соответствует ASCII YYYY-MM-DD и реальна; категория строго из rules, id непустой, сумма Decimal конечна и >=0. Неверное число полей — отклонение с причиной. Неверный заголовок/нечитаемый файл/сломанный CSV — явная ошибка, успешный результат не возвращается.

## Решения для неописанных границ

Это допущения координатора для обратимых локальных случаев, а не дополнительные факты задания. Сначала валидировать, затем исключать полные повторы валидных строк; каждый повтор неверной записи остаётся rejected. Полный повтор — совпадение четырёх исходных значений CSV. Если уже принят тот же id с другими значениями, последующая запись отклоняется как конфликт id; первая сохраняется. Пробелы и регистр не нормализовать. Decimal допускает дробные суммы, ноль и запись экспонентой, если конечна; вывод — обычный десятичный формат. В тестах проверить NaN/Infinity. Материалы H07 эти допущения не затрагивают.

## Reporting

`src.reporting.summarize(clean_rows, categories) -> dict`

- clean_rows по контракту выше; categories — dict rules['categories'].
- Возврат: `{'clean_rows': int, 'total': Decimal, 'category_totals': dict[str, Decimal]}` с русскими названиями всех категорий, включая нулевые. Никаких float, повторной очистки или импорта cleaning.py.

`src.reporting.render_report(clean_rows, stats, sources, rules) -> str`

- sources — список имён обработанных файлов, stats по Cleaning, rules загружен из JSON.
- UTF-8 Markdown на русском: список sources, число уникальных операций, общая сумма KZT, таблица трёх категорий, баланс (все четыре числа), явные допущения валидации/полных повторов/конфликтов. Детерминированный текст без времени запуска, случайных ID и абсолютных путей машины. Значения без потери десятичной точности.

## CLI и независимая проверка

Из каталога решения: `python3 -m src.pipeline --input input --output result` (директории). Входы: nov-1.csv, nov-2.csv, rules.json. Три выхода: clean.csv (`id,date,category,amount`), rejected.csv (`source,line_number,raw_line,id,reason`), report.md. CSV newline='', UTF-8. Повторный запуск заменяет три собственных выхода, не дописывает строки. Ошибка чтения/контракта/записи даёт ненулевой код и конкретную диагностику.

`python3 -m src.verify --input input --output result --expected checks/expected.json` независимо проверяет артефакты против исходных строк и фиксированных эталонных чисел, без вызова clean_files/summarize/render_report. Проверяет строки/схемы/уникальность, источник и сырой текст отклонений, причины по соответствующим дефектам, точные суммы и баланс отчёта. Удалённая/изменённая/добавленная запись, подмена rejected или неверная сумма отчёта отклоняются ненулевым кодом. Проверка комплекта H07, не универсальный валидатор любых бухгалтерских данных.

Тесты: `python3 -m unittest discover -s tests -v` из каталога решения. Выходы unittest Red/Green сохраняются в evidence соответствующего владельца. Никакого фиктивного успеха и постоянных заглушек.

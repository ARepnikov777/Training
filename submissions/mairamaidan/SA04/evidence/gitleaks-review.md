# Gitleaks: результат и разбор находки

CLI использован с --redact. Перед коммитами staged-проверка завершалась кодом 0, без находок; проверка истории `gitleaks git --redact .` завершилась кодом 1, одна находка. Код 1 не объявляется успешной проверкой и не подавляется. Конфигурация сканера не менялась, исключения не добавлялись.

Метаданные: generic-api-key, `materials/H09/checksums.json:3`, исходный коммит `22aad84cc6666d2b0abca011e95a96b12e69c9cd`. Найденная строка — элемент контрольных сумм для `checks/key-points.md`, не изменение SA04. Само найденное значение здесь не приводится.

Координатор проверил значение без вывода в чат/лог: это 64 шестнадцатеричных символа и оно равно SHA-256 реального содержимого `materials/H09/checks/key-points.md` в том же коммите. Следовательно, эта находка — подтверждённое ложное срабатывание на контрольной сумме, а не API-ключ. История и материалы не переписывались. Наличие такого результата фиксируется при сдаче отдельно от чистого staged-сканирования.

Воспроизводимый способ проверки: через `git show` прочитать JSON и указанный файл на закреплённом коммите, сравнить значение JSON с hashlib.sha256(file_bytes).hexdigest(), выводить только результат сравнения. Повторная проверка всей истории обязательна перед push.

# SA07: интерфейсы (утверждены до параллельной работы)

Версия: v1.0. Владелец файла: координатор. Любое изменение после старта
записывается в `run-log.md` с причиной и новой версией.

Корень решения: `submissions/wilddancer-oss/SA07/` (дальше пути от него).
Исходный комплект: `materials/H06/` в репозитории (только чтение, совпадает с
`downloads/H06.zip`, SHA-256 `16414ca4…ebeee`).

## Общие правила

- Кодировка UTF-8, CSV через запятую, первая строка - заголовок, значения с
  запятыми в кавычках. Десятичная точка.
- Таймкод - `MM:SS` от начала `meeting.mp3`. Диапазон - `MM:SS-MM:SS`.
  Несколько таймкодов в одном поле - через `; `. Все таймкоды в пределах
  `00:00-11:25` (длительность 685,73 с, `input/audio-info.json`).
- Ссылка на заметку - `input/notes.md:N`, где N - номер строки файла
  (строка 1 - заголовок, строки 3-9 - утверждения).
- Неизвестное значение пишется явно: `не указан` (ответственный, срок, сумма).
  Пустая ячейка допускается только в необязательных полях, перечисленных ниже.
- Имена людей - как в записи: `Анна`, `Илья`, `Мария`.

## Словарь тем (`topic`) - ключ сверки аудио и заметок

| topic | О чём |
| --- | --- |
| `date` | дата практикума |
| `room` | аудитория |
| `start_time` | время начала |
| `archives` | архивы заданий |
| `stand` | локальный стенд |
| `files_check` | проверка материалов/файлов, приёмка |
| `coffee` | кофе-брейк |
| `stickers` | наклейки |
| `budget` | бюджет и организационные расходы |
| `audience` | число слушателей, компьютеры |
| `other` | всё остальное (в `statement` пояснить) |

Новая тема добавляется только координатором (новая версия файла).

## Словарь видов события (`kind`)

`proposal` - предложение, ещё не решение; `decision` - принятое решение;
`change` - решение, заменяющее прежнее; `cancellation` - отмена прежнего
предложения или решения; `question` - открытый вопрос; `info` - факт без решения.

## 1. Первый результат распознавания (worker audio)

- `asr/first-pass.json` - сырой вывод инструмента: список сегментов
  `{"id", "start", "end", "text"}`, `start`/`end` в секундах.
- `asr/first-pass.md` - те же сегменты в виде `[MM:SS-MM:SS] текст`.
- `asr/method.md` - инструмент, версия, модель, точная команда/скрипт,
  время запуска, SHA-256 входного MP3 и выходного JSON.
- `asr/transcribe.py` - скрипт распознавания.

Коммит с этими файлами делается **до** открытия `checks/transcript.md` и
`checks/timeline.json` кем-либо из участников.

## 2. `extract/audio-events.csv` (worker audio)

Заголовок:

```
event_id,start,end,speaker,kind,topic,value,owner,deadline,statement,asr_quote
```

- `event_id` - `A01`, `A02`, … по времени.
- `speaker` - имя, если его можно установить по записи, иначе `не указан`.
- `value` - значение (дата, номер, сумма, время) или пусто.
- `owner`, `deadline` - из записи или `не указан`.
- `statement` - краткий пересказ своими словами.
- `asr_quote` - дословный фрагмент `asr/first-pass.md`, на котором основано событие.

## 3. `extract/notes-claims.csv` (worker notes)

Заголовок:

```
claim_id,notes_ref,notes_text,topic,field,value,owner,deadline
```

- `claim_id` - `N1`…`N7` (по одному на утверждение; составное утверждение
  можно разбить на `N1a`, `N1b`).
- `notes_ref` - `input/notes.md:N`; `notes_text` - точная подстрока этой строки.
- `field` - что утверждается: `date`, `room`, `start_time`, `deadline`,
  `amount`, `status`, `owner`.

## 4. Итоговый пакет (worker package, один владелец)

### `asr/corrections.md`

Таблица исправлений первого результата: таймкод, было (first-pass), стало,
основание (`checks/transcript.md` и/или прослушивание сегмента), влияет ли на
решение. Плюс: сколько сегментов сверено, сколько исправлено.

### `result/minutes.md`

Разделы в этом порядке:

1. `## Реквизиты встречи` - что известно о встрече, с таймкодами.
2. `## Действующие решения` - нумерация `Р1`, `Р2`…, у каждого таймкод и,
   если есть, ссылка на заметку.
3. `## История изменений` - что предлагали, что изменили или отменили, кто и
   когда (таймкоды всех шагов).
4. `## Открытые вопросы` - то, что не решено на встрече.
5. `## Источники` - MP3, заметки, распознавание, исправления.

Отменённое решение есть только в «Истории изменений», в «Действующих
решениях» его нет.

### `result/tasks.csv`

```
task_id,action,topic,owner,deadline,source_timecode,source_quote,confirmation_status
```

- Только действующие поручения. Отменённое в файл не попадает.
- `source_timecode` - таймкод события `decision`/`change` той же темы из
  `extract/audio-events.csv`, на котором основано поручение.
- `confirmation_status`: `подтверждено записью` | `срок не указан в записи` |
  `ответственный не указан в записи` | `требует уточнения`.

### `result/contradictions.csv`

```
contradiction_id,topic,notes_ref,notes_fragment,audio_timecode,audio_fragment,kind,resolution,resolution_status
```

- `kind`: `дата`, `место`, `время`, `срок`, `ответственный`, `сумма`,
  `отмена`, `обязательность`, `нет в записи`.
- `resolution` - что принято по источнику и почему.
- `resolution_status`: `разрешено по записи` | `не разрешено`.

## 5. Проверка координатора

`tools/check_package.py` (только stdlib). Запуск из корня решения:

```
python3 -I tools/check_package.py .
```

Код 0 - находок нет, 1 - есть находки (список в stdout), 2 - ошибка вызова.
Проверяет: файлы и заголовки, словари, формат и предел таймкодов, ссылки на
строки заметок и подстроки, что каждый `source_timecode` задачи попадает в
событие `decision`/`change` той же темы, что темы с последним событием
`cancellation` отсутствуют в `tasks.csv` и упомянуты в «Истории изменений».
Это механическая проверка. Смысл таймкодов по звуку проверяет reviewer.

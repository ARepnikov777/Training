# SA07: декомпозиция

Родительская задача: [#58](https://github.com/ARepnikov777/Training/issues/58).
Веха и номера подзадач - в README после создания.

## Почему пять подзадач

Работа естественно делится по входам и выходам: правила комплекта (чтение),
аудио, заметки, сведение в пакет, независимая проверка. Меньше нельзя:
сведение и проверка не должны делаться тем же агентом, а аудио и заметки
независимы и идут параллельно. Больше не нужно: протокол, задачи и
расхождения опираются на одну и ту же сверку, и разносить их по разным
исполнителям значит дать трём людям править одну логику и общие таймкоды.
Поэтому весь итоговый пакет у одного владельца.

## Граф зависимостей

```
T1 explore ─┬─> T2 audio ─┐
            └─> T3 notes ─┴─> T4 package ─> T5 review
```

T2 и T3 параллельны: T2 читает только `meeting.mp3`/`audio-info.json`, T3
только `notes.md`; выходы не пересекаются; общий интерфейс `interfaces.md`
утверждён координатором до их запуска.

## Текст вехи

**SA07 · wilddancer-oss**

Результат: рабочий пакет по планёрке практикума «Орион» в
`submissions/wilddancer-oss/SA07/result/`: `minutes.md` (протокол с
действующими решениями и историей изменений), `tasks.csv` (действие,
ответственный, срок, таймкод, статус подтверждения), `contradictions.csv`
(заметка, запись с таймкодом, характер расхождения, решение). Выполнено по
графу `workflow.md` субагентами explorer, worker, reviewer.

Критерии приёмки:
- три файла переданы; решения и расхождения с таймкодами и ссылками на заметки;
- отменённое решение (кофе-брейк) не в действующем списке, история изменения понятна;
- ответственные и сроки из источников либо `не указан`; неразрешённое не скрыто догадкой;
- первый результат распознавания сохранён до сверки с эталоном, есть способ и список исправлений;
- граф проверен до запуска, run-log подтверждает реальные запуски, отрицательный сценарий и отчёт независимого reviewer;
- один PR в `main`, merge - преподаватель.

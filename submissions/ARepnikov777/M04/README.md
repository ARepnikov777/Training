## Результат и открытие

- [Страница 1 — CSV](result/page-1.csv): 20 шт., 128000 KZT.
- [Страница 2 — CSV](result/page-2.csv): 40 шт., 256000 KZT.
- [Страница 3 — CSV](result/page-3.csv): 60 шт., 384000 KZT.

CSV: UTF-8 без BOM, разделитель — запятая, десятичный разделитель — точка.
В Excel используйте «Данные → Из текста/CSV», выберите UTF-8 и запятую.
Первая строка содержит название ведомости, вторая — заголовки пяти столбцов;
строки 3–6 — товары A101–A104, строка 7 — ИТОГО. Названия столбцов с запятыми
заключены в кавычки по правилам CSV. Пустые поля сохранены. Единицы — шт. и KZT.
В редакторе текста файлы также открываются; формулы и оформление для CSV не предусмотрены условием.

## Как получены данные и как повторить

Инструменты: Codex (визуальное чтение трёх изображений), Python 3.12.3
и его стандартная библиотека (`zipfile`, `base64`, `zlib`, `struct`, `csv`, `json`,
`hashlib`, `decimal`). Сторонний OCR не применялся. Установка PyMuPDF во временном
окружении была отменена; для результата он не использовался и не требуется.

1. Из корня репозитория распакуйте `downloads/M04.zip` в отдельную временную папку
   через `python3 -m zipfile -e downloads/M04.zip /tmp/m04-repeat`.
   Условия и уточнения сохранены в [issue-25.md](evidence/issue-25.md).
2. Откройте распакованный `M04/input/scan.pdf` любым локальным PDF-просмотрщиком.
   Для текущего выполнения встроенные RGB-изображения PDF (объекты 3, 5, 7,
   1190×1684 пикселей) были декодированы из ASCII85/Flate и сохранены без изменения
   пикселей: [страница 1](evidence/page-1.png), [2](evidence/page-2.png), [3](evidence/page-3.png).
3. Прочитайте три таблицы визуально. Перенесите заголовки, все ячейки и название
   ведомости в CSV по описанной выше структуре. Сначала сохраните первичное чтение;
   наше чтение до открытия контрольного ответа — [initial-transcription.json](evidence/initial-transcription.json).
   Использованный запрос к агенту сохранён в [prompt.md](evidence/prompt.md).
4. Повторно сравните все ячейки с соответствующей страницей PDF; сомнения фиксируйте
   по странице, артикулу и столбцу. Затем откройте `checks/expected.json`, проверьте
   контрольные итоги. Эталон не использовался для первоначального заполнения.
5. Проверьте результат командой ниже. Сценарий проверяет целостность исходников,
   структуру, соответствие первичной транскрипции, произведения количества на цену,
   суммы строк, строку ИТОГО и контрольные значения. Визуальную сверку он не заменяет.

```bash
python3 submissions/ARepnikov777/M04/evidence/verify.py
```

Команду запускайте из корня репозитория; при запуске из другой папки укажите
абсолютный путь к `verify.py`. Дополнительные пакеты не нужны; не используйте `python -O`.
Исходные `materials/M04/` и `downloads/M04.zip` должны оставаться на своих местах.
Фактический вывод: [verification.txt](evidence/verification.txt).
Повторный запуск из `/tmp` также прошёл. На временной копии намеренно изменена
сумма A101 первой страницы с 20000 на 20001: проверка завершилась с ошибкой,
как и требовалось; [результат отрицательной проверки](evidence/negative-check.txt).

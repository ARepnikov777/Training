# Требования из issue (копия для исполнителей)

## Issue #60 (SA09), предметная часть — дословно
Пользователь — один координатор на своём компьютере; многопользовательский доступ и авторизация не требуются. Карточка содержит `id`, `title`, `description`, `status`. Название после trim — 1–100 символов. Статусы строго **«новая», «в работе», «готово»**. Новая карточка создаётся со статусом «новая». Данные сохраняются после перезагрузки и повторного запуска. Поиск — по части названия без учёта регистра, фильтр — по статусу.

В комплекте есть `import-valid.csv` и `import-mixed.csv` с рабочими поручениями. CSV UTF-8 использует схему `id,title,description,status`; повторный импорт существующего `id` обновляет запись. Для плохих строк нужно показать номер, считая заголовок строкой 1, и причину; хорошие строки из того же файла должны сохраниться. Удаление, почтовые уведомления, роли пользователей и внешний сервер не нужны.

Интерфейс должен позволять координатору создать и отредактировать карточку, сменить статус, найти/отфильтровать заявки, импортировать и экспортировать CSV.

Сценарий использования: координатор импортирует корректный файл, редактирует задачу и переводит её в работу; затем импортирует смешанный файл и видит принятые записи отдельно от ошибок. После перезапуска изменения сохраняются. Экспорт и обратный импорт контрольного набора не создают лишние копии и сохраняют значения. Reviewer проходит сценарий на чистом локальном хранилище.

Предметные критерии:
- Работают создание и редактирование карточек, поиск и смена статуса по заданному брифу.
- Данные сохраняются между запусками приложения.
- Импорт принимает корректные строки и сообщает номера и причины ошибок остальных без молчаливой потери данных.
- Экспорт соответствует схеме; повторный импорт экспортированного контрольного набора сохраняет согласованные значения.
- Переданы исходники, инструкция запуска и результаты всех выданных пользовательских сценариев.

## Issue #39 (H03), уточнения — дословно
Дополнительные контрольные сценарии: (1) поиск «ПРОВЕРИТЬ» находит «Проверить скан» без учёта регистра и не включает другую запись; (2) фильтр статуса «готово» оставляет только соответствующие задачи, снятие — весь список; (3) повторный импорт T001 с изменёнными title/description/status обновляет поля без новой записи; (4) экспорт всех записей и импорт в чистый экземпляр сохраняют id и поля; (5) import-mixed.csv принимает T003 и сообщает ошибки строк 3 и 4, где заголовок считается строкой 1. Для сохранения можно использовать локальное хранилище; сторонняя СУБД не обязательна.

Работа выполняется на своём компьютере. Локальный стенд использует Python 3.10+ без сторонних пакетов.

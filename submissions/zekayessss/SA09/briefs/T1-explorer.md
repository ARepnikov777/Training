## Задача
Составь **контракт** локального приложения «Заявки практикума», по которому два исполнителя смогут независимо и параллельно написать (а) сервер с хранением и CSV и (б) веб-страницу. Технология зафиксирована координатором: Python 3.10+ только стандартная библиотека (`http.server`, `json`, `csv`), сервер на `127.0.0.1`, данные в JSON-файле, страница — статические HTML/JS/CSS, которые отдаёт тот же сервер. Не придумывай требований, которых нет во входах; если правило во входах не задано — так и пометь и предложи минимальный вариант, отметив его как «решение контракта».

## Что вернуть (Markdown, готовый к сохранению в contract.md)
1. Схема карточки: поля, типы, правила валидации (trim, длина 1–100, ровно 3 статуса, статус по умолчанию), правила для `id` (кто генерирует при создании через UI, формат).
2. Хранение: формат файла, путь по умолчанию, переопределение пути (аргумент командной строки `--data`), атомарность записи, поведение при отсутствии файла.
3. HTTP API: для каждого эндпоинта — метод, путь, параметры, тело запроса, успешный ответ (JSON-пример), ошибки (код + JSON-пример текста ошибки на русском). Обязательно: список с поиском `q` и фильтром `status`, создание, редактирование (title/description/status), импорт CSV, экспорт CSV.
4. Импорт CSV: кодировка (UTF-8, допустим BOM), обязательный заголовок, нумерация строк (заголовок = 1), какие ошибки строк бывают и их точный текст, обновление по существующему `id`, как плохие строки не мешают хорошим, формат ответа (принятые / ошибки с номерами).
5. Экспорт CSV: заголовок, порядок строк, экранирование, кодировка.
6. Запуск: команда, порт по умолчанию, флаги.
7. Таблица: каждый из 6 сценариев `cases.json` и 5 сценариев из уточнений #39 → какие вызовы API/действия UI его проверяют и ожидаемый результат.
8. Разделение файлов между исполнителями: storage-worker — `app/store.py`, `app/server.py`, `tests/test_store.py`; ui-worker — только `app/static/` (`index.html`, `app.js`, `style.css`). Пути относительно `submissions/zekayessss/SA09/`.

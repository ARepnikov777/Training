## Что сделать
Реализуй по контракту: `TaskStore` (раздел 8, РК-21), валидацию (раздел 1), хранение (раздел 2), импорт/экспорт CSV (разделы 4–5), HTTP API и раздачу статики (раздел 3), запуск (раздел 6). Python 3.10+, только стандартная библиотека.

Тесты `tests/test_store.py` (unittest, во временном каталоге, без сети):
- создание: статус «новая», id `C0001`, trim названия; пробелы → `ValidationError`, ничего не сохранено; 101 символ → ошибка;
- редактирование: title/description/status; недопустимый статус → ошибка и запись не изменилась; неизвестный id → `NotFoundError`;
- сохранение: новый экземпляр `TaskStore` на том же файле видит данные;
- поиск без учёта регистра («ПРОВЕРИТЬ» → только T001), фильтр по статусу;
- импорт `import-valid.csv` дважды → 2 created, затем 2 updated, всего 2 записи;
- импорт `import-mixed.csv` → accepted T003 (строка 2), ошибки строк 3 и 4 с текстами контракта;
- **корректная строка после плохих не теряется** (плохая строка 2, хорошая строка 3 → хорошая принята);
- обновление T001 повторным импортом без новой записи;
- экспорт → импорт в чистый `TaskStore` сохраняет все поля; повторный импорт в исходный → только updated;
- ошибки файла: не UTF-8, пустой, неверный заголовок → `FileFormatError`, хранилище не изменилось;
- поле с запятой/кавычкой/переводом строки переживает экспорт-импорт.

Плюс один короткий smoke-тест HTTP: поднять сервер в потоке на свободном порту с временным `--data`, проверить `GET /api/tasks`, `POST /api/tasks`, `POST /api/import`, `GET /api/export`.

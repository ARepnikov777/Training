# H04 — пакет PDF

Обработаны три пригодных документа: пять страниц, из них четыре растровые; извлечена таблица 6 × 5 с заголовком и итоговой строкой. `04-broken.pdf` зарегистрирован как ошибка чтения. Выполнена собственная визуальная сверка исполнителя; независимое ревью не заявляется.

## Результат

- [Постраничный индекс](result/page-index.csv): исходный файл, номер страницы, метод, первичный и проверенный текст, изображение.
- [Таблица](result/03-rotated-table/table-1.csv) и [происхождение всех 30 ячеек](result/03-rotated-table/table-1-cells.csv): исходное OCR-значение, проверенное значение, координаты, уверенность движка, ссылка на raw.
- [Проверка фрагментов и арифметики](result/verification.csv), [неопределённости](result/uncertain.csv), [ошибки](result/errors.csv).
- [Первичный результат](evidence/primary-raw/manifest.json), [его SHA-256](evidence/primary-raw-sha256.json), [протокол визуальной сверки](evidence/visual-review.md).
- [Условие issue #40 с уточнениями](evidence/issue.json); исходный полный комплект находится в `kit/H04/` и не изменён.

CSV: UTF-8, запятая, десятичная точка; импорт в Excel через «Из текста/CSV». Номера страниц, строк и столбцов начинаются с 1; строка 1 таблицы — заголовок. Координаты ячеек в пунктах PDF относительно страницы после установки поворота 0°, начало сверху слева. `source.png` сохраняет исходный поворот, `normalized.png` показывает страницу для OCR.

## Запуск

Проверено на Windows, Python 3.15.0, Node.js 26.13.1, npm 11.20.0. Использованы PyMuPDF 1.26.7, Tesseract.js 6.0.1, модели `@tesseract.js-data/rus` и `eng` 1.0.0. Прямые Python-зависимости закреплены в `requirements.txt`, дерево npm — в `package-lock.json`. После установки обработка локальна: OCR не использует API и не скачивает модели из сети.

Из этой папки, в PowerShell:

```powershell
New-Item -ItemType Directory -Force .cache | Out-Null
$env:TEMP = Join-Path (Get-Location) '.cache'
$env:TMP = $env:TEMP
$env:PYTHONIOENCODING = 'utf-8'
python -m venv .venv
& .venv/Scripts/python.exe -m pip install --cache-dir .cache/pip -r requirements.txt
npm ci --cache .cache/npm --ignore-scripts
& .venv/Scripts/python.exe batch.py --output .cache/fresh-raw
```

Последний вызов намеренно возвращает **код 1**, поскольку содержит непригодный PDF. Нулевой код означает, что все документы обработаны без ошибок. При ожидаемом результате в `manifest.json` три статуса `ok` и один `error`; `errors.csv` содержит `FileDataError` для `04-broken.pdf`. Открывайте оба файла после запуска. Продолжение **после** ошибки проверяет тест, где повреждённый PDF идёт первым.

Выходной каталог должен быть новым: существующий каталог скрипт не перезаписывает. Для следующего прогона выберите другое имя. Можно задать `--input PATH` и `--languages rus+eng` (по умолчанию); английские тестовые картинки обрабатываются с `eng`. `batch.py` извлекает текстовый слой, рендерит страницы и вызывает локальный `ocr.cjs` для сканов и отдельных ячеек. Для данного комплекта поворот PDF нормализуется к 0°; ограничение алгоритма таблиц — одна прямоугольная сетка с длинными линиями. Произвольный наклон скана и произвольные многотабличные макеты не входят в проверенный контракт.

Первый запуск был сохранён в `evidence/primary-raw/` **до открытия** `kit/H04/checks/expected.md`. Raw включает нативный текст, OCR JSON с фактическими confidence/TSV/blocks, исходные и нормализованные изображения, отдельные изображения/JSON ячеек, CSV и журнал процесса. Снимок хешей сделан до сверки. Повторный запуск финального кода сравнен с ним: [протокол](evidence/reproducibility.json).

`result/` — проверенная вручную копия. Повторная пакетная обработка создаёт raw; ручные исправления воспроизводятся по [протоколу](evidence/visual-review.md). Исходные OCR-ошибки намеренно сохраняются в raw, а точечные изменения отражены в `reviewed_value`/`review_note`.

## Проверки

```powershell
& .venv/Scripts/python.exe -m pip install --cache-dir .cache/pip -r requirements-dev.txt
& .venv/Scripts/python.exe -m unittest -v test_batch
& .venv/Scripts/ruff.exe check batch.py test_batch.py
node --check ocr.cjs
# Из корня репозитория:
& submissions/EnterFC/H04/.venv/Scripts/python.exe -m pytest -q tests submissions/EnterFC/H04/test_batch.py
```

TDD: [RED](evidence/tdd-red.txt) — четыре ожидаемых AssertionError на отсутствующих результатах, без ошибок импорта/окружения; [GREEN](evidence/tdd-green.txt) — 4/4. Дополнительный [RED языка OCR](evidence/language-red.txt) фиксирует влияние русского словаря на английский тестовый текст; параметр языка исправляет причину без подстановки ожидаемых значений. Итоговый общий прогон: [13 passed](evidence/pytest-final.txt), включая 9 проверок исходного репозитория; [линтер](evidence/lint-final.txt). PyMuPDF выдаёт один DeprecationWarning о `ByteString` на Python 3.15; это предупреждение зависимости сохранено в логе.

Числа confidence взяты у Tesseract и не трактуются как вероятность точности. Для текстового слоя confidence отсутствует. Произвольный порог не используется: **все OCR-страницы и ячейки подлежат визуальной сверке**. В `result/` явно указано, что сверка выполнена исполнителем. Растровое изображение не позволяет доказать исходный Unicode-алфавит одинаково выглядящих `A/А`; обозначения нормализованы по описанному соглашению, эта неопределённость остаётся открытой.

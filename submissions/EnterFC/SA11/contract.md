# Контракт результатов SA11

Обработчик возвращает `list[dict]` успешных страниц. Интегратор формирует пакет `{"pages": [...], "errors": [...]}`; ошибка документа находится только в `errors`, обработка остальных документов продолжается. Все поля обязательны, дополнительные поля запрещены.

Страница:

```json
{"source":"03-rotated-table.pdf","page":1,"method":"ocr","text":"Таблица","tables":[{"columns":["Название","Значение"],"rows":[["Итого","12"]]}],"uncertainty":["Проверить число"]}
```

- `source` — непустое имя исходного PDF; `page` — целый номер страницы с 1 (в Python `int`, не `bool`); `method` — непустое название метода.
- `text` — строка, может быть пустой; `tables` — список таблиц. У таблицы `columns` — список строк заголовков, `rows` — список строк таблицы, каждая строка — список строковых ячеек. Таблица наследует `source`, `page` и `method` своей страницы.
- `uncertainty` — список строк с сомнительными местами страницы, включая таблицы; пустой список означает отсутствие отмеченных сомнений. Пустые таблицы и списки допустимы. Согласованность количества ячеек и содержательная точность не проверяются контрактом.

Ошибка документа:

```json
{"source":"04-broken.pdf","error":"Не удалось открыть PDF","continued":true}
```

`source` и `error` — непустые строки; `continued` строго `true`. Ошибка не содержит полей страницы.

`src/contract.py`: `validate_page(record)` и `validate_batch(payload)` возвращают `None` при успехе и выбрасывают `ValueError` при нарушении структуры. `schema.json` описывает пакет в JSON Schema 2020-12; JSON Schema считает `1.0` целым числом, однако Python API принимает для `page` только `int`. Валидация структуры не подтверждает наличие файла, число страниц, качество OCR и правильность извлечённых данных.

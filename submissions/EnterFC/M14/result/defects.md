# Два класса дефектов M14

Общие условия: неизменённая копия комплекта, Python 3.15.0, `mode=form-buggy`, `http://127.0.0.1:18764/register`, форма с `novalidate`, синтетические данные. Все ожидания взяты из input/scenarios.md и issue #35. Проверка через поля и кнопку Orca browser, ответы сохранены наблюдателем fetch; сохранение подтверждено GET /api/registrations.

## D1 — неверный формат email сохраняется

1. Перезагрузить форму, ввести имя `Анна`.
2. Ввести `not-an-email`, установить согласие и нажать «Отправить» (сценарий 3).
3. Для второго проявления снова перезагрузить форму, ввести `Анна`, `a b@example.test`, согласие, отправить (сценарий 6).

Ожидается: HTTP 400, ошибка `email`, новая запись не появляется. Адрес в первом случае не содержит @ и домена, во втором содержит пробел.

Фактически: HTTP 201, «Регистрация сохранена», новые записи. В сценарии 3 id `a754ccd5-1c94-4c42-b9af-3739aca2d3b4`, число записей 1 → 2; в сценарии 6 id `e98d9a5a-fa69-419c-b7ae-1a0a66b3eb4a`, число записей 4 → 5. Это один класс ошибки с двумя проявлениями.

Доказательства: [3 JSON](../evidence/browser/scenario3.json), [3 PNG](../evidence/browser/scenario3.png), [6 JSON](../evidence/browser/scenario6.json), [6 PNG](../evidence/browser/scenario6.png). Полный token и тело ответа содержатся в JSON.

Установленная причина: `registration_errors()` в `result/site/serve.py` пропускает `re.fullmatch` при `buggy=True`; остаётся только проверка непустого email. Конфигурация включает form-buggy. Влияние: сервер сохраняет адреса, запрещённые контрактом. Исправление намеренно не выполнялось.

## D2 — имя длиной 81 символ принимается

1. Перезагрузить форму (отдельный token).
2. Ввести ровно 81 кириллическую строчную `а`, `s4@example.test`, установить согласие.
3. Нажать «Отправить» и проверить сохранённые регистрации.

Ожидается: длина после trim равна 81 и превышает 80; HTTP 400 с ошибкой `name`, без новой записи.

Фактически: HTTP 201, «Регистрация сохранена: 503bb916-610f-49d7-b713-a3ada065d4e5», число записей 2 → 3. Контроль граничного допустимого значения 80 выполнен отдельно и прошёл (сценарий 5, HTTP 201).

Доказательства: [4 JSON с полной строкой](../evidence/browser/scenario4.json), [4 PNG](../evidence/browser/scenario4.png), [5 JSON](../evidence/browser/scenario5.json), [5 PNG](../evidence/browser/scenario5.png), длины в [CSV](matrix.csv).

Установленная причина: `registration_errors()` допускает `120 if buggy else 80`. Браузером доказано принятие 81; вся граница 120/121 не проверялась. Влияние: сохраняются имена сверх договорённой длины. Исправление намеренно не выполнялось.

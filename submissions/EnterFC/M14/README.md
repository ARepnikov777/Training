# M14 — проверка учебной формы

Проверены все 8 сценариев: **PASS 1, 2, 5, 7, 8; FAIL 3, 4, 6**. Найдены два намеренных класса дефектов: отсутствие проверки формата email и неверная верхняя граница имени. Код формы и сервера не исправлялся.

## Результат и доказательства

Перед публикацией координатор заменил 8 синтетических token учебной формы согласованными обозначениями `test-token-01` … `test-token-08` во всех текстовых evidence и CSV. Это псевдонимизация опубликованной копии: исходные наблюдения сохранены локально вне Git, остальные поля запросов/ответов и id не менялись. Равенство token между отправками и их различие между свежими формами сохранены. [Протокол](evidence/token-pseudonymisation.json). Значения не являются настоящими API-ключами; Gitleaks распознал случайные строки в полях token как generic-api-key. Исключения/отключение сканера не использовались; повторный staged scan после замены — exit 0, no leaks found.

Независимое [ревью](reviewer-report.md) приняло предметный результат. Его ограничения перечислены явно: живой стенд reviewer повторно не запускал, некоторые сводные поля verification.json не являются самостоятельным доказательством браузерного поведения.

- [Матрица и первичный отчёт](result/initial-report.md): все входы, ожидания, фактические ответы, число записей и ссылки на снимки.
- [Редактируемая матрица CSV](result/matrix.csv): UTF-8, запятая; полные строки имён, длины, token/id, статусы и условия начала каждого сценария.
- [Отчёт о дефектах](result/defects.md): воспроизведение, влияние, доказательства и причина.
- [Протокол браузерных команд](evidence/browser/commands.json): команды Orca, ответы, время UTC. JSON каждого сценария содержит реальный запрос/ответ, текст результата и список сохранённых записей; PNG и DOM snapshot фиксируют видимую форму.
- [Исходные условия issue #35](evidence/issue.json), включая уточнения сценариев 7/8. [Источник комплекта](evidence/provenance.json), [хеши до](evidence/input-hashes-before.json), [итоговая проверка целостности](evidence/verification.json).

## Запуск и повторение

Фактически использованы Python 3.15.0, стандартная библиотека Python, PowerShell, Git, Orca CLI и встроенный браузер Orca. Никакие внешние формы, адресаты, API-ключи или удалённые серверы не использовались. Данные синтетические, email использует `.test`.

Из `submissions/EnterFC/M14/` запустить в терминале:

```powershell
python result/site/serve.py --port 18764
```

Открыть `http://127.0.0.1:18764/register`. При занятом порте выбрать свободный и поменять адрес. Сервер слушает только `127.0.0.1`. Использованная конфигурация `mode=form-buggy`, `synthetic=true`; встроенная HTML-валидация отключена `novalidate` по условию. Сервер пишет только в рабочую копию `result/site/_state.json`, исходный `kit/M14/` неизменяемый.

Для чистого повторения после остановки собственного сервера переименовать `result/site/_state.json`, например в `_state.previous.json`, затем запустить сервер. Сохранённый `_state.json` относится к представленному прогону и содержит 7 вымышленных регистраций. Остановка сервера — Ctrl+C.

В сценариях **1–6 каждый раз перезагрузить форму** и вводить отдельные данные из CSV. `а × 81/80` означает кириллическую строчную `а`, точная строка есть в CSV и JSON; длина определяется после trim. Для всех случаев установить согласие.

**Сценарий 7:** открыть свежую форму, заполнить `Анна`, `s7@example.test`, согласие; отправить и дождаться успеха HTTP 201. **Без перезагрузки и изменения полей** нажать «Отправить» повторно. Ответ HTTP 200 возвращает тот же id/token; число записей после первой и повторной отправки равно 6 → 6. Общий переход 5 → 6 в матрице включает первоначальную успешную отправку. Доказательства: [первый успех JSON](evidence/browser/scenario7-first.json), [PNG](evidence/browser/scenario7-first.png), [повтор JSON](evidence/browser/scenario7-repeat.json), [PNG](evidence/browser/scenario7-repeat.png).

**Сценарий 8:** начать с ещё одной свежей формы, оставить имя пустым, заполнить `s8@example.test`, согласие. Отправить: HTTP 400 `errors=["name"]`, записей 6. **Без перезагрузки** ввести только имя `Анна` и снова отправить: HTTP 201, token прежний, записей 7. Прежняя успешная регистрация не используется как старт этого сценария. Доказательства: [отказ JSON](evidence/browser/scenario8-empty.json), [PNG](evidence/browser/scenario8-empty.png), [исправление JSON](evidence/browser/scenario8-fixed.json), [PNG](evidence/browser/scenario8-fixed.png).

При желании автоматизировать тот же прогон: создать отдельную страницу `orca tab create --url http://127.0.0.1:18764/register --json`, взять `browserPageId`, затем `python result/run_scenarios.py --page <browserPageId>`. CLI `orca` должен быть доступен либо явно передан через `--orca`. Скрипт заполняет реальные поля и нажимает кнопку через Orca. Обёртка `fetch` только копирует фактические ответы и не меняет запросы/ответы/правила. Повторный запуск перезаписывает evidence/browser, поэтому доказательства текущего прогона следует предварительно сохранить отдельно. UUID при повторении будут другими.

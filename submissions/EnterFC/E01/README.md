# E01 — копирование файлов по категориям

Решение задания [#7](https://github.com/ARepnikov777/Training/issues/7): все 12 файлов скопированы в [result](result/), по четыре в documents, images и tables. Копии побайтово совпадают с исходниками. Полные условия и уточнения сохранены в [evidence/issue.json](evidence/issue.json).

Использованы нативный субагент Codex, PowerShell, Python 3.15.0 и стандартная библиотека Python (pathlib, shutil, argparse, unittest, hashlib, subprocess, tempfile, json). Бриф исторически озаглавлен «исполнителю Claude», но Claude worker не запускался. Проверки ниже — самопроверка исполнителя, не независимое ревью.

Из корня репозитория перейдите в папку решения:

```powershell
cd submissions/EnterFC/E01
python -B sort_files.py kit/E01/input/files result-fresh
python -B -m unittest -v test_sort_files.py
python -B verify_result.py
```

Python 3.10+; сторонние пакеты для решения не нужны. Папка назначения должна отсутствовать: для следующего запуска задайте другое новое имя. Сохранённый результат уже находится в result; его можно открыть проводником. Содержимое PDF/PNG и текстовых файлов копируется без преобразований.

verify_result.py сверяет сохранённый result с эталоном, сравнивает байты и хеши, затем запускает скрипт из временной чистой папки на свежей копии input. Временная папка создаётся внутри решения и автоматически удаляется. Обновляются evidence/input-after.json и evidence/verification.json; исходники и result не меняются. Эталон checks был впервые прочитан после успешного сохранения первого результата ([лог](evidence/first-run.txt)).

## Definition of Done (DoD)

- [x] В выходной папке находятся все 12 файлов в категориях из задания; содержимое файлов совпадает с исходниками.

  Результат: documents — 4, images — 4, tables — 4. verify_result.py проверил точный состав относительно checks/expected.json и прямое сравнение байтов для всех 12 пар. Для каждой пары SHA-256 и bytes_equal находятся в [evidence/verification.json](evidence/verification.json).

- [x] Исходная папка не изменена; ни один исходный файл не удалён и не перезаписан.

  Результат: имена и SHA-256 всех 13 файлов input, включая rules.md, до и после совпадают: [до](evidence/input-before.json), [после](evidence/input-after.json). Все 16 записей контрольных сумм исходного комплекта также совпадают; [доказательство](evidence/verification.json).

- [x] Переданы скрипт и инструкция запуска; повторный запуск на свежей копии даёт ожидаемое распределение.

  Переданы [sort_files.py](sort_files.py), команды выше и [verify_result.py](verify_result.py). Повтор из чистой папки со свежим input дал те же 12 выходов и SHA-256, входная копия не изменилась: fresh_copy_repeat_matches и fresh_input_unchanged в [отчёте проверки](evidence/verification.json).

## TDD и ограничения

[Пять поведенческих тестов](test_sort_files.py) проверяют распределение, байты, сохранность входов, повтор на свежей копии и запрет выхода внутри входной папки. RED: четыре ожидаемых AssertionError, одна проверка сохранности уже проходит на пустой заглушке; ошибок импорта/окружения нет. GREEN: все пять проходят. Доказательства: [заглушка](evidence/tdd-skeleton.py.txt), [RED](evidence/tdd-red.txt), [GREEN](evidence/tdd-green.txt).

Область скрипта — плоская папка файлов этого задания с расширениями .txt/.md/.json/.pdf/.png/.csv в нижнем регистре. Вложенные каталоги и неизвестные расширения не поддерживаются. При существующей выходной папке скрипт завершается ошибкой; выход внутри входа запрещён. При ошибке файловой системы возможен частичный новый результат: исправьте причину и используйте новую папку. Не заменяйте пути исходников результатом.

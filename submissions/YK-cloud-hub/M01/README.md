# M01 — сортировщик файлов

Задание: [#22](https://github.com/ARepnikov777/Training/issues/22).
Исполнитель: YK-cloud-hub. Решение локальное; PR не опубликован.

`starter.py` рекурсивно копирует `.txt`/`.md` в `documents`, `.csv` в
`tables`. Исходные пути сортируются; коллизии получают `__2`, `__3` и далее.
Существующие файлы не перезаписываются, источник сохраняется.
По умолчанию выполняется только предпросмотр. `--apply` подтверждает запись.
Журнал JSON в stdout содержит `source`, `target`, `action`, `reason`.
Неизвестные расширения и символические ссылки пропускаются с объяснением.

## Запуск

Из корня репозитория (Python 3.9+, только стандартная библиотека):

```sh
python3 submissions/YK-cloud-hub/M01/starter.py \
  submissions/YK-cloud-hub/M01/source/M01/input/files /tmp/m01-output-new

# После просмотра списка подтвердить копирование:
python3 submissions/YK-cloud-hub/M01/starter.py \
  submissions/YK-cloud-hub/M01/source/M01/input/files /tmp/m01-output-new --apply

python3 -m unittest discover -s submissions/YK-cloud-hub/M01 -v
```

Для записи журнала можно перенаправить stdout в отдельный файл вне источника.
Сам сортировщик в dry-run ничего не записывает; перенаправление создаёт файл
средствами оболочки. `evidence/preview.json` и `applied.json` — сохранённые
журналы первого запуска из чистой временной рабочей папки. Абсолютные пути
в них относятся к рабочему каталогу этого запуска.

Реализация одним агентом; отдельный субагент выполнил статическое ревью.
Он нашёл пересечение выходной папки с источником; проблема воспроизведена
в [регрессионном Red](evidence/review-red.txt) и исправлена.

Источник и выход не должны содержать друг друга. Ошибки чтения и записи
дают сообщение в stderr и код 1. Операция не транзакционная: при ошибке
часть копий может остаться; перед повтором следует осмотреть выход.
Повторный запуск создаёт новые имена, не перезаписывая предыдущие копии.
Предпросмотр отражает текущее состояние; изменения файлов между ним и
`--apply` не блокируются. Конкурентная коллизия при записи вызывает ошибку.
Журнал успешного запуска выдаётся после завершения; при ошибке следует
проверить stderr и фактически созданные файлы.

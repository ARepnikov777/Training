# Материалы курса по агентной разработке

45 самостоятельных учебных комплектов. Все документы, люди, товары и числа синтетические. Никакие материалы от преподавателя дополнительно не требуются.

Для выполнения задания откройте его issue, скачайте ZIP по ссылке «Скачать комплект», распакуйте и прочитайте README внутри. Браузерные стенды работают локально на Python 3.10+ без дополнительных пакетов. Для создания изображений дан вариант без платного генератора. Эталонные данные находятся в checks; алгоритмы решений не выданы.

## Подготовка и сдача задания

Все слушатели имеют право записи в этот репозиторий. Работайте в отдельной ветке и сдавайте **одно задание одним Pull Request в `main` этого же репозитория**. Fork не нужен. Напрямую в `main` результаты не отправляем.

### 1. Подготовь задание

1. Выбери задание или возьми назначенное преподавателем. Напиши в его issue: «Беру в работу», указав свой GitHub-логин и код задания.
2. Прочитай цель, входные правила и все пункты Definition of Done (DoD). Скачай ZIP из issue, распакуй и проверь, что исходные файлы открываются; для браузерного задания запусти вложенный локальный стенд.
3. До реализации сформулируй план и способ проверки результата по каждому пункту DoD. Неясность требований уточни в issue до работы, не подменяй её догадкой.
4. Клонируй репозиторий один раз. Перед новым заданием обнови локальную `main` и создай свою ветку. Пример для E01; замени `LOGIN` своим GitHub-логином:

   ```bash
   git clone https://github.com/ARepnikov777/Training.git
   cd Training
   git switch main
   git pull --ff-only origin main
   git switch -c student/LOGIN/E01
   ```

   Если репозиторий уже клонирован, первые две команды не нужны: перейди в его папку. Перед переключением ветки сохрани работу по предыдущему заданию в её собственной ветке.

### 2. Выполни и проверь

- Работай с копией исходных материалов. Выданные `materials/`, `downloads/`, общие инструменты и результаты других слушателей не изменяй.
- Создай папку `submissions/LOGIN/E01/` для своего результата. Если задача просит исправить готовый проект, помести его исправленную версию в эту папку. В ней должны быть:
  - `README.md` — что сделано, какие инструменты использованы, как открыть или запустить результат и какие ограничения остались;
  - сам результат: код, документы, таблицы, изображения или автоматизация браузера;
  - редактируемые исходники и промпты, если они использовались;
  - доказательства проверки: результаты тестов, контрольные числа, скриншоты или отчёт. Можно выделить для них папку `evidence/`.
- В `README.md` своего решения скопируй **все пункты DoD из issue**. Для каждого укажи фактический результат и доказательство: команду, число, ссылку на файл или скриншот. Невыполненные пункты оставь явно незакрытыми.
- Для исправления программного дефекта покажи падение нового регрессионного теста до исправления и прохождение после. Документы и изображения открой и проверь визуально. Повтори запуск по своей инструкции из чистой рабочей папки.
- В Git добавляй только относящиеся к решению файлы. Не добавляй токены, пароли, реальные персональные данные, виртуальные окружения, зависимости, кеши и вложенные Git-репозитории. Из исправленного учебного проекта переноси файлы решения без его каталога .git.

### 3. Открой PR

Сохрани результат в своей ветке и отправь её в этот репозиторий:

```bash
git add submissions/LOGIN/E01
git diff --cached --check
git diff --cached
git commit -m "[E01] Решение задания"
git push -u origin student/LOGIN/E01
```

В GitHub открой Pull Request: **base — `main`, compare — `student/LOGIN/E01`**, оба в `ARepnikov777/Training`.

- Название: `[E01] LOGIN — короткое название результата`.
- В описании укажи `Задание: #7` (номер соответствующего issue), путь к решению, что сделано, как проверено и оставшиеся ограничения. Заполни предложенный шаблон PR.
- После проверки преподавателем исправляй замечания новыми коммитами **в той же ветке и том же PR**. После изменений повтори затронутые проверки и обнови доказательства.
- Работа считается принятой после одобрения преподавателя и слияния PR в `main`. Самостоятельно свой учебный PR не объединяй.
- После приёмки и подтверждённого слияния PR преподаватель оставляет в связанном issue итог со ссылкой на PR и результатами проверок, затем закрывает issue как выполненное (`Completed`). Одного одобрения без слияния для закрытия недостаточно. Повторное использование задания следующими слушателями не отменяет закрытие принятой задачи.

## Пересборка для организатора

Python 3.14, зависимости из requirements-build.txt, шрифт DejaVu Sans и libespeak-ng с русским голосом, ffmpeg. Команда: `python tools/build_materials.py`. Для слушателя пересборка не нужна: готовые PDF, PNG и MP3 включены. Проверка: `python -m pytest tests -q`, `ruff check tools tests`, `ruff format --check tools tests`. Намеренно неисправный код лежит только в учебных input/project и стендах mode=*-buggy; проверки самого комплекта должны проходить.
